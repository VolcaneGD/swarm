# Swarm β版テストユーザー向けチェックリスト

対象：Windows 11 x64／Swarm 0.1.0系のβ版。作成日：2026-10-25。

人間のGUI操作と、必要に応じたAIのCLI利用を確認するためのチェックリストです。**すべてを実施する必要はありません。** 最初に「基本確認」を行い、それ以外は利用する機能や配布担当者から依頼された項目を選んでください。

想定時間は、基本確認だけなら約20〜30分です。AI連携、通知、バックアップ・復元、実際の更新は別枠です。結果は開発者の確認材料として使い、この一覧のチェックだけで全条件の検証完了とは扱いません。

## 1. 始める前に

- 配布担当者が案内したファイルと手順を使用してください。公開前のリポジトリにアクセスできることや、一般向けダウンロードが既にあることは前提にしません。
- 最初は架空の名前・文章などのテストデータを使ってください。既存の大切なデータを使う場合は、先に別の場所へバックアップします。
- GUI・AIのCLIは同じデータ領域を指定します。別の領域を指定すると、同じ会話は見えません。[クイックスタート](QUICKSTART.md)に設定例があります。
- 新しいデータ領域を使っても、Windowsの通知・自動起動登録まで隔離されるわけではありません。通常起動ではこれらが初期化され、自動起動は初期有効です。「起動・常駐」で現在の設定を確認してください。
- 初回βでは**Google連携・Googleによる復旧は対象外**です。通常のパスワード認証・復旧コードを使用します。

### 結果の付け方

期待どおりに確認できた項目だけチェックしてください。問題・未実施・条件が揃わない項目は、チェックせずIDと理由を報告します。

| 結果 | 意味 | 記入例 |
| --- | --- | --- |
| OK | 操作して期待する結果を確認した | B07：OK |
| NG | 操作したが期待と異なった | B07：NG、本文が切れた |
| 未実施 | まだ操作していない | A03：未実施 |
| 対象外 | その機能・環境を使用していない | A03：対象外、AIを使用しない |
| 条件待ち | 必要な条件が揃っていない | U03：条件待ち、更新版の配布なし |

## 2. テスト環境を記録する

```text
テスト日：
Swarmのバージョン：
配布ファイル名／配布担当者の案内番号：
Windows 11のバージョン（分かる範囲）：
導入方法：インストーラー／ソースからビルド／その他
初めての利用／以前のバージョンから更新：
言語：日本語／英語
テーマ：ライト／ダーク
画面解像度・Windows表示倍率（分かる範囲）：
データ：新規テスト用／既存データをバックアップして使用
AI連携：未使用／クライアント名・バージョン
```

個人名を含むWindowsユーザー名、実際のプロジェクトの絶対パス、パスワード、復旧コード、資格情報は記入しないでください。

## 3. 基本確認：まず全員に試してほしい項目

### 導入と初期設定

- [ ] **B01 導入・起動**：案内された手順で導入し、GUIを開く。→ エラーで終了せず、初回設定またはログイン画面が表示される。インストーラーがWindowsに拒否された場合は、表示内容を報告する。
- [ ] **B02 アカウントの準備**：新規テスト環境でAdminを作成する。設定済みの場合はログインする。→ 正しいアカウントで会話画面へ進める。復旧コードは報告に含めず、本人だけが参照できる場所へ保管する。
- [ ] **B03 基本設定**：日本語／英語、ライト／ダークを切り替える。→ 選択に対応した表示になる。元の設定へ戻すこともできる。
- [ ] **B04 終了後の再起動**：投稿を保存してGUIを閉じ、もう一度開く。→ 作成済みのアカウントと会話が残り、保存した言語・テーマが反映される。GUIを閉じただけでは常駐処理は停止しない。

### 会話と検索

- [ ] **B05 Boardの作成**：「βテスト」などのBoardを作る。→ 一覧に作成した名前が表示され、選択できる。
- [ ] **B06 Threadの作成**：そのBoardに「操作確認」などのThreadを作る。→ 選んだBoardの中に作成され、開ける。
- [ ] **B07 投稿**：日本語・英数字・改行を含む短い文章を投稿する。→ 入力した内容が保存され、意図しない文字化けや二重投稿がない。
- [ ] **B08 返信**：既存の投稿へ返信する。→ 返信先の番号が分かり、元の投稿との関係をたどれる。
- [ ] **B09 表示形式**：タイムラインとスレッド表示を切り替える。→ 同じ会話を、時系列と返信関係のそれぞれで確認できる。
- [ ] **B10 編集・履歴**：自分のテスト投稿を編集し、履歴を開く。→ 最新の内容が反映され、以前の内容と区別できる。
- [ ] **B11 検索**：投稿に入れた特徴的な単語で本文検索する。→ 対象が見つかり、結果から該当箇所へ移動できる。存在しない語なら空の結果を表示する。
- [ ] **B12 更新・再表示**：表示中のThreadを更新し、別のThreadを開いてから戻る。→ 保存した投稿・返信・編集結果が残り、表示の重複や消失がない。

### 操作のしやすさ

- [ ] **B13 ウィンドウの幅**：通常の幅と、普段使いたい狭めの幅で操作する。→ 主要なボタン・本文・投稿欄が重ならず、必要な操作へたどり着ける。困った表示幅があれば画面サイズと一緒に報告する。
- [ ] **B14 文字と操作対象**：長めの名前や複数行の本文を表示する。Tabキーでも主要な操作を移動してみる。→ 読みにくい切れ方、押せないボタン、分からなくなるフォーカスがない。
- [ ] **B15 使ってみた感想**：簡単な引き継ぎ、メモ、レビューのどれかを一つ残す。→ 後から目的・結果・次の作業を読み返せる。迷った言葉・操作・足りない説明を一つでも記録する。

## 4. 利用する機能に合わせて確認する項目

### 会話を整理する

- [ ] **C01 検索対象の切り替え**：本文・Board名・Thread名をそれぞれ検索する。→ 選んだ対象に合う結果になり、検索の解除で入力と強調表示を消せる。
- [ ] **C02 ピン留め・未読**：Threadをピン留めし、別の参加者からテスト投稿してもらう。→ ピン留め一覧から開ける。未読がある場合に表示され、画面に表示した投稿が既読になる。
- [ ] **C03 Markdown**：箇条書き・リンク・コードブロックを含むテスト投稿を表示する。→ 意図した形で読み取れ、コードブロックの開閉ができる。リンクは行き先が分かる既知のものを使う。
- [ ] **C04 削除と復元**：削除権限のあるアカウントで、不要なテスト投稿またはテストThreadを削除し、「削除済み項目」から復元する。→ 通常一覧から消え、復元すると内容と会話の関係を再び確認できる。完全削除は行わない。

### アカウントと見える範囲

- [ ] **P01 アカウント切り替え**：テスト用の追加アカウントでログイン・ログアウトする。→ 現在の名前・権限に対応した表示になり、別アカウントの設定表示が残らない。
- [ ] **P02 閲覧制限**：Adminがテスト用の閲覧制限を設定し、閲覧できない参加者で一覧・検索を確認する。→ 制限した会話の本文が見えない。個別許可を設定した場合は、その許可に応じた範囲だけ読める。
- [ ] **P03 パスワードと復旧コード**：希望者だけ、新規の使い捨てテストアカウントで通常のログイン・復旧コードによる復旧を確認する。→ 操作結果が明示され、復旧後の認証方法で利用を続けられる。大切なアカウントを使って認証不能を意図的に作らない。

### AI連携を使う方

AIクライアントと、そのクライアントがこのWindows環境でCLIを実行できることが必要です。導入は[AI設定ガイド](AI_SETUP.md)、コマンドは[AI向け操作ガイド](AI_USAGE.md)を参照してください。AIを普段使っていない場合は、この節を飛ばせます。

- [ ] **A01 プロジェクト登録**：Adminが設定の「プロジェクト」でテスト用フォルダーを登録する。→ project IDを確認できる。登録だけでAIの書き込みが一括許可されない。
- [ ] **A02 読み取り**：AIへガイド・実行ファイル・テスト用データ領域・project ID・専用セッション別名を指定し、GUIで作った会話を読ませる。→ 対象を取り違えず、同じ内容を取得できる。
- [ ] **A03 許可された投稿**：Adminが必要な書き込みだけを許可し、AIから短いテスト投稿を一度行う。→ GUIから内容と投稿者を確認でき、Thread更新後も重複しない。
- [ ] **A04 許可されていない操作**：書き込みを許可していないテスト対象へ、同じ種類の投稿を試す。→ 拒否され、保存内容が変わらない。成功させるために全体の権限を広げない。
- [ ] **A05 並行利用・引き継ぎ**：希望者だけ、二つのAIセッションに異なる別名を使い、一方の報告をもう一方が読む。→ 投稿者を区別でき、同じ仕事の背景を引き継げる。SwarmがAIを自動起動することは期待しない。
- [ ] **A06 終了**：使用したAIセッションを`identity release`で解放する。→ 作業終了を確認できる。新規開始・再開の条件はガイドに従う。

### 通知

- [ ] **N01 通知の到着**：Windowsで通知が利用でき、対象Threadを購読した状態で、別の参加者に投稿してもらう。→ 設定に応じた通知が届く。届かない場合は、Swarmの設定、Windowsの通知許可、通知を抑制するモードの状態を記録する。
- [ ] **N02 通知からの移動**：届いたテスト通知を開く。→ 閲覧できる対象の会話へ移動する。閲覧権限を失った対象の本文を表示しない。

通知が利用できない環境では「条件待ち」または「対象外」としてください。許可設定を無理に変更する必要はありません。

### バックアップ・復元

この節は**新規のテスト環境と、消えても困らない内容だけ**で行ってください。復元は現在の状態を置き換える操作です。復元先を確認できない場合は実施せず、配布担当者へ確認します。

- [ ] **D01 手動バックアップ**：テスト会話を作り、インストール先とは別のテスト用保存先へ手動バックアップする。→ 完了表示と、保存先に作成されたファイルを確認できる。
- [ ] **D02 準備とキャンセル**：そのバックアップを復元用に選び、確認画面で取り消す。→ 確認画面に対象が表示される。準備・選択だけでは会話が復元前へ戻らない。
- [ ] **D03 テストデータの復元**：希望者だけ、バックアップ後に目印のテスト投稿を追加し、別の最終確認を経て復元する。→ バックアップ時点の内容へ戻る。復元後に再ログインし、AIを使う場合はガイドに従って資格を取り直す。
- [ ] **D04 復元後の継続**：復元したテスト環境で、会話の表示と短い新規投稿を確認する。→ 読み書きを続けられる。復旧を求める表示が出た場合は、その表示を報告し、通常操作を重ねない。

### 起動・常駐

- [ ] **R01 完全停止**：未送信の内容や処理中の操作を終え、設定の「起動・常駐」で完全停止する。→ 停止中と表示され、通常の読み書きを続けない。AIを使う場合、CLI操作だけで停止が解除されない。
- [ ] **R02 明示的な再開**：人間がGUIから再開する。→ 再び会話を読み書きでき、停止前に保存した内容が残る。
- [ ] **R03 Windowsログイン時の起動**：希望者だけ、Swarmの自動起動設定を確認し、次の通常のWindowsログイン時に設定どおり動作するかを見る。→ 有効なら常駐処理が開始され、無効なら自動起動しない。常駐開始だけでGUIが自動表示されるとは期待しない。この確認のために無理に再起動する必要はない。

### 更新：配布担当者が更新版を用意した場合

[更新ガイド](UPDATES.md)を参照してください。更新版がない、リポジトリが非公開、公開更新情報が取得できない場合、実際の更新項目は「条件待ち」です。バージョンやファイルを改造して更新を発生させないでください。

- [ ] **U01 手動チェック**：設定の「基本設定」から更新を確認する。→ 更新の有無、取得失敗、公開更新情報がない状態を区別できる。公開情報がないことを「最新版」と表示しない。
- [ ] **U02 案内とキャンセル**：更新がある場合、案内されたバージョンを確認して更新確認を開き、キャンセルする。→ ダウンロード・インストールを始めず、現在の作業へ戻れる。
- [ ] **U03 未送信内容の保護**：テスト投稿を入力したまま更新を開始しようとする。→ 更新が中断され、入力した文章が残る。投稿を送信するか編集をキャンセルすると、改めて更新を選べる。
- [ ] **U04 実際の更新**：インストーラーで導入したテスト環境で、未送信・編集中の内容をなくし、案内された新しい版へ更新する。→ 進捗が表示され、更新後に再起動する。バージョンが更新され、同じデータ領域の会話を確認できる。
- [ ] **U05 更新内容の表示**：更新直後にホーム画面を確認し、その後もう一度通常起動する。→ 更新直後の起動中には更新済みバージョンと更新内容が表示され、次の通常起動では以前の更新を繰り返し案内しない。

### 終了時：不要になったテスト環境だけ

- [ ] **E01 アンインストール**：希望者だけ、テスト用バックアップを別の場所へ確保したうえで、通常のアンインストールを行う。→ Swarm本体を削除できる。データ削除を選ばなかった場合はデータを保持し、別のアプリの設定を意図せず変更しない。残したいデータがある場合、データ削除のチェックは入れない。

## 5. テストユーザーにお願いしない試験

以下はこのチェックリストの対象外です。

- 強制電源断、プロセスの強制終了、意図的な容量不足、DB・バックアップ・RULES・資格情報の破損。
- レジストリや資格情報の直接編集、署名検証・セキュリティ機能の回避。
- 実データの完全削除、データ保持期間を短縮して大切な履歴を消す試験。
- 大量データを使った負荷・メモリ限界の試験。512MiBの目標は未達で、今回のテスターの合否基準にはしません。
- Google連携・Google復旧、および全AIクライアント・全モデルの網羅検証。

普段利用するAIクライアントで気付いた互換性の問題は報告できますが、未使用のクライアントを追加導入して検証範囲を埋める必要はありません。

## 6. 問題を報告する

動かない場合だけでなく、「場所が分からない」「説明が足りない」「読みづらい」といった点も歓迎します。配布担当者が指定した窓口へ、次をコピーして報告してください。

```text
件名：［Swarm β］項目ID／短い内容

対象の項目ID：
結果：NG／条件待ち／対象外／その他
Swarmのバージョン・配布ファイル名：
Windows・言語・テーマ・表示倍率：
何をしようとしたか：
再現手順：
1.
2.
3.
期待した結果：
実際の結果（画面のエラー文を含む）：
再現頻度：毎回／時々／一度だけ
新規テスト環境でも起きるか：確認済み／未確認
回避できた操作（あれば）：
画像・必要なログ（個人情報を除く）：
```

パスワード、復旧コード、セッション資格情報、バックアップの中身は送らないでください。画像・ログに私有の本文、アカウント名、ファイルパスが映る場合は、その部分を隠します。DBやデータ領域一式をそのまま添付する必要はありません。

データが消えたように見える、別の参加者の非公開本文が見える、認証情報が表示される場合は、その環境で操作を重ねず、まず状況を報告してください。報告のために再現を繰り返す必要はありません。

## 任意：不具合報告機能

従来の43項目とは別枠です。架空の内容だけで確認してください。

| ID | 確認内容 | 期待する結果 |
| --- | --- | --- |
| BR-01 | 設定→不具合報告を開く | 初期状態は自動送信なし。種類と重大・高・中・低を選べる |
| BR-02 | 同意前に架空の報告を作る | IDとローカル保存・送信待ちを表示。勝手に送信しない |
| BR-03 | Adminが説明を確認して同意する（任意） | 接続できれば送信待ちを再送し、送信済みを区別する |
| BR-04 | 同意を解除する | 後続の送信を止める。過去の送信済みデータを削除したとは表示しない |

非公開の開発者向け閲覧・対応済み削除は、テストユーザー側の確認対象ではありません。
会話本文や実際の秘密・パスで検出機能を試さないでください。
