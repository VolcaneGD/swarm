Swarm reads one explicitly named local report file for `identity start`, `identity resume` or `identity model`. It does not scan client homes, launch clients/inference, configure their hooks or request a remote response. Local LLM harnesses vary by user; supported response formats are optional inputs, not a required product/runtime.

Supply all three options together: `--model-client`, `--model-session-id`, `--model-report-file`. OpenAI-compatible responses additionally require `--model-project-root` with an existing absolute registered project path. Select the current report deliberately; there is no newest-file heuristic or ongoing watcher.

The added adapters use maintained public contracts: [Hermes export source](https://github.com/NousResearch/hermes-agent/blob/63d0b94120027d487c9a5235b9ec64b696af1b26/hermes_state_portability.py), [OpenClaw export source](https://github.com/openclaw/openclaw/blob/c2aad8ebac866dac2fe862228f53862a969c200c/src/trajectory/export.ts), [Gemini hooks](https://geminicli.com/docs/hooks/reference/), [OpenCode v2 transfer schema](https://github.com/anomalyco/opencode/blob/836c0e5e65279eb054b9b445050f2b159c8c81a5/packages/schema/src/session-transfer.ts) and [native export command](https://opencode.ai/docs/cli/#export) with the observed1.14.30 legacy fields, [Cursor output](https://cursor.com/docs/cli/reference/output-format), [Copilot event types](https://github.com/github/copilot-sdk/blob/main/nodejs/src/generated/session-events.ts). They do not open live client databases, install hooks, launch agents or send network requests. Saved JSON exports are limited to1MiB; event JSONL is64MiB total/1MiB per record. Hermes bulk exports, Cursor private editor stores and undocumented formats outside the explicitly described native legacy/v2 contracts remain unsupported.

Sources documented as permitting a missing working directory require the explicit registered project root as caller-supplied context; it does not prove native client ownership. Unknown latest selection does not revive an older model. Model/harness fields are report metadata, not executable instructions or backend attestation. Actual adoption is scoped to dated evidence in AI_SETUP; full all-client acceptance remains pending. Native Computer Use GUI tests are held by user instruction; in-app-browser and non-GUI tests remain allowed.

OpenCode exports are single JSON objects bounded to1MiB. Legacy user/assistant records must belong to the selected session; assistant cwd must match the top-level directory. A redacted/missing/relative directory cannot be replaced by explicit root. Do not infer cwd from path.root or bodies. Native --sanitize may redact directory and therefore yield an unusable model report: use a private metadata-only copy of genuine native fields with bodies removed, preserving selector/cwd/model fields, rather than manufacturing a v2 transfer. These inputs are still client claims, never authentication.

Antigravity's [official hook common fields](https://www.antigravity.google/docs/hooks) are supported for saved SessionStart/PreInvocation or other hook inputs. Save the current hook input through your existing client/harness configuration and pass that explicit file; Swarm does not install hooks or select a newest conversation. Tool arguments, transcript paths, artifact paths and other fields are never forwarded. Older internal protobufs, headless stream output and undocumented exports are unsupported. Model placeholders still fall back to declared/unknown. Workspace URIs must be converted to existing absolute filesystem directories by the harness; URI strings are not accepted as directories.

```powershell
swarm --session agent identity model --model-client antigravity --model-session-id CONVERSATION_ID --model-report-file hook-input.json --model-project-root C:/Projects/Example
```

The example requires an existing protected alias and a real matching report/project; placeholders are not successful client adoption. Hook selection metadata does not attest the responding backend model.

The common Service canonicalizes normalized report roots and checks the selected project's registered paths before using a reported model. These roots and selectors are caller-reported context, not authenticated client ownership. The selector filters this read; Swarm session credentials/aliases govern lifetime, concurrency and resume. It does not persist an external client-session binding or prove that a response belongs to the currently executing client.

`automatic` means extraction from the listed field, including Codex's selected-model snapshot. It does not verify the backend's actual weights, routing, aliases or fallback. An AI can forge a local report or normalized claim; source labels do not grant permissions. A caller-supplied `--model-name` is `declared`, never automatic. The normalized report wins over that fallback; if a structurally valid matching report has no usable model, the declared fallback wins, otherwise the name/source is `不明`/`unknown`. Malformed files, foreign selectors, unsupported formats and missing required flags fail with sanitized `INVALID_INPUT`; they do not silently use fallback.

When execution is known to be local but the model name is unavailable, use `--local-model`. The name is then `ローカルモデル` with `unknown` provenance. A usable reported or declared name takes precedence. The flag describes supplied locality; OpenAI compatibility, file location and product name alone never establish locality. A known name cannot be replaced with an unknown placeholder. Resolving an unknown local name preserves the Swarm ID and deadline; past Post names remain their original snapshots.

JSONL is bounded to64MiB total and1MiB per line; single response JSON is bounded to1MiB. Read growth is checked against the same limits. Complete final JSONL records need no final newline; malformed/truncated records fail. Synthetic/default/auto/unknown placeholders are excluded. A synthetic latest main response cannot revive an older model. Only normalized client/selector/root/basis/name fields reach the private identity route; bodies and report-file paths do not. Existing protected pending intents also bind model report/locality fields, and changed retry inputs conflict. After an uncertain identity request, retry identical input or inspect status; do not overwrite pending state or use a new alias merely to conceal uncertainty.

Unknown-name enrichment preserves the ID/deadline; a known model-name change requires a new identity. Explicit resume still requires the same project/model and saved resume credential, rotates credentials and preserves existing provenance. Repeating a declared name never downgrades an automatic source. No automatic migration or rewriting of existing identities/posts occurs.

Valid report reads also carry the supported client identifier when the model is unknown. The shared identity route retains a harness label for each supported named client in existing versioned app metadata. Generic OpenAI-compatible JSON does not identify a harness and leaves its name unknown. A different known harness requires a new identity; unknown enrichment does not renew expiry. New Post/Response author metadata snapshots this label transactionally. Existing posts without a snapshot remain unknown; their historical model/display ID is not rewritten. The GUI author label is `No.number ID: display (model: harness)`; missing values localize to unknown, and human USER markers are not model names. Harness metadata is client-reported context, not authentication or backend attestation.
