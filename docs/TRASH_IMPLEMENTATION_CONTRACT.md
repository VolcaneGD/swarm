# Trash and storage lifecycle contract — 2026-10-16

User explicitly requests permanent deletion of deleted Boards/Threads, individual and checkbox/bulk restore/purge, retention of deleted Boards/deleted Threads/archived Threads, and no undeletable accumulating data. This overrides the prior soft-delete-only boundary for these human operations. Publication and existing Data protection remain unchanged.

Implementation contract for this task:

- New human operations board.purge/thread.purge require corresponding explicit new human permissions (Admin implicitly permitted), a currently deleted target and confirmed:true; AI public routes never expose them. Board purge includes its descendant Threads/Posts/revisions and associated conversation state. Thread purge includes its Posts/revisions/state. Live targets are refused. No restore after physical removal; parent identifiers and numbering of surviving Threads are never reused.
- Human conversation.batch accepts {action:"restore"|"purge",items:[{kind:"board"|"thread",id:string}],confirmed:true}. Validate unique targets/current authority/current deleted state. Perform the batch atomically in the Service transaction; restore parents before selected children, normalize purge child targets covered by selected parents. Do not silently operate on unselected siblings. Refuse stale/unauthorized batches without partial commit. Transport size limits still apply, without silently truncating selections.
- conversation.deleted supplies eligible deleted items with can_restore/can_purge and parent_deleted for Threads, including explicitly deleted children of deleted Boards when current human authority permits seeing their parent/metadata. UI exposes all those rows, disables individual restore until parent restored, but permits selected parent+child restore in the atomic batch. Select all operates on displayed eligible items; the confirmation lists exact items and cascade impact.
- Extend retention settings {history_days,deleted_days,deleted_board_days,deleted_thread_days,archived_thread_days}. Positive integer or null; missing new fields from older callers preserve current values, initial migration sets null. Existing history_days/deleted_days semantics remain. Archived age starts when the Thread becomes archived (at the1000Post boundary); migrate an archived timestamp safely from existing last-Post time. Automatic purge can remove expired deleted Boards/Threads or expired archived Threads through the same internal deletion owner. Never change the host clock for tests.
- UI uses Bulk Actions, checkbox selection and explicit review/confirmation; individual Restore/Permanently delete buttons have8px+gap and wrap. Bilingual copy and preview behavior must match real contracts. Busy/error/partial stale UI is fail-closed, drafts/selection survive rejected operations. No native security/authentication UI automation.
- Reclaim SQLite free pages/WAL safely after committed purges, without losing data or claiming forensic deletion. Clean conversation-dependent changes/notifications/pins/unread/UI state; preserve security/account configuration and active transaction recovery prerequisites. Body-free creation receipts retain the existing7day expiry to prevent delayed creation retries from recreating purged Boards/Threads; maintenance removes expired receipts even without new creation. This is bounded temporary metadata, not a permanent tombstone. Review other accumulating stores (including backups/receipts/cache) for existing deletion/pruning routes and implement missing authorized routes rather than claiming all done from conversation deletion alone. Old backups are separate copies; disclose their independent lifecycle.

Workers have disjoint file ownership; main agent owns IPC/type integration, source verification, inventories and final acceptance. Never build shared frontend output concurrently or touch production runtime52064/default Data/old fixtures. Same OS incident retry budget remains exhausted. No public release.
