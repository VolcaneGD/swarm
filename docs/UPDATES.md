# 更新チェックとアプリ内アップデート

## 利用者向け

起動時に一度、次の公開更新情報を確認します。設定の「基本設定」→「アプリの更新」→「更新を確認」から手動で再確認できます。

0.1.3以降は、このセクションに実行中アプリの「現在のバージョン」も表示します。

0.1.2／0.1.3で「更新を準備中…」から進まない場合は、更新用TLS初期化の不具合が
あります。準備済み修正版0.1.4では初期化とエラー返却を修正しています。旧版自身の
アプリ内更新ではこの修正を受け取れないため、アプリを閉じて修正版のインストーラーを
手動実行してください。既存のDataは削除・再作成しないでください。
公開されている更新先のバージョンとは別に、ネット接続や更新確認の成否に依存せず確認できます。

```text
https://github.com/VolcaneGD/swarm/releases/latest/download/latest.json
```

新しい安定版がある場合はバージョンと「今すぐアップデート」を表示します。確認画面で未送信の投稿を保存し、「更新して再起動」を選びます。通常のNSISインストーラーで導入したSwarmが対象で、ソースから直接起動した開発用バイナリーは更新を実行しません。

1. 未送信の投稿や開いている編集・作成フォームがあれば中断して内容を保持します。送信・保存または編集のキャンセル後に再試行できます。画面設定の保存を確認し、配布ファイルをダウンロードします。
2. 埋め込みの公開鍵でファイル署名と署名されたバージョンを検証します。URLはこのリポジトリの対応バージョンのインストーラーだけを受け付けます。取得中に新しい入力を行った場合も、停止直前に未送信の内容と設定保存を再確認します。準備の確認後は入力を一時停止し、後から入力した内容を失う競合を防ぎます。
3. 保存するウィンドウ情報と更新記録を準備し、認証済みの人間の停止経路でruntimeを安全に停止します。処理中の認証・投稿などを安全に確定できない場合は中断します。
4. インストーラーを`/UPDATE`で起動して現在のGUIを終了します。既存のDataとPATH所有記録を維持します。GUI・CLI・runtimeが終了しない場合はインストーラーが中断し、強制終了はしません。
5. インストール後にアプリを再起動します。明示指定した`--data-dir`も引き継ぎます。実際の起動バージョンが更新記録と一致した場合、ホーム画面に更新内容を一度表示します。

キャンセルした確認ではダウンロード・インストールを行いません。ファイル取得・署名検証の失敗はruntimeの停止前に中断します。停止後にインストーラー起動が失敗した場合、runtimeは停止したままなので「起動・常駐」から明示的に再開できます。失敗した更新を完了済みとして表示しません。

**リポジトリが非公開、または公開済みの更新情報がない間は利用できません。** アプリにGitHubのトークンを埋め込んだり、利用者のGitHub資格情報を要求したりしません。GitHub側が404を返す場合は、最新であるという表示と区別して、公開更新情報がないことを案内します。

## 通信と署名

起動時・手動確認時は公開JSONを取得し、利用者が更新を選んだ場合だけインストーラーを取得します。送信するのは通常のHTTP要求で、会話本文、アカウント情報、パスワード、復旧コード、バックアップは送信しません。GitHubと配布CDNには通常の接続情報が伝わります。

Tauri Updaterの署名は配布物とバージョンを検証するためのものです。WindowsのAuthenticode署名とは別で、Authenticode署名済みであることを意味しません。TLS検証やバージョン比較を無効にして更新を通す実装はありません。

## 配布担当者向け

公開鍵は`apps/desktop/src-tauri/tauri.conf.json`の`plugins.updater.pubkey`に固定しています。対応する秘密鍵はソース・配布物・GitHubへ含めず、所有者管理の別の場所で保管・バックアップします。既存利用者への更新を維持するために必要な鍵なので、更新ごとに作り直さないでください。

バージョンはworkspace、Tauri設定、frontend package情報を揃え、三つの実行ファイルを同時にビルドします。配布先はWindows x64のNSISです。ビルド済みインストーラーから、公開に必要なファイルをローカルで準備できます。

```powershell
./scripts/prepare_update_release.ps1 `
  -Installer '<BUILT_INSTALLER_PATH>/Swarm_0.1.0_x64-setup.exe' `
  -Version '0.1.0' `
  -NotesFile '<RELEASE_NOTES_PATH>' `
  -SigningKeyPath '<PRIVATE_KEY_PATH_OUTSIDE_REPOSITORY>' `
  -OutputDirectory '<SWARM_SOURCE_ROOT>/target/distribution/update-release-0.1.0'
```

出力先は新規の`target/distribution`配下に限定します。署名ツールはTauri CLIです。秘密鍵が暗号化されている場合は`TAURI_SIGNING_PRIVATE_KEY_PASSWORD`をその実行プロセスへ設定します。秘密値を文書やコマンド履歴に貼り付けないでください。

準備するファイル：

- `Swarm_<VERSION>_x64-setup.exe`
- 同名の`.exe.sig`（`--app-version`を指定した署名）
- `latest.json`（バージョン、更新内容、Windows向けURLと署名）
- `SHA256SUMS.txt`

`v<VERSION>`のGitHub Releaseへこれらを同時に載せます。`latest.json`は最新の公開安定版Releaseのassetとして取得されます。署名と実際の配布ファイルを一致させ、公開後に取得・検証してください。プレリリース・旧版・同版の強制導入は行いません。

この準備スクリプトはアップロード、Release作成、リポジトリ公開を行いません。非公開ソースの更新指示だけで、実配布やPublicへの切り替えを実行しないでください。

実際のGitHub配布を経由した更新・インストーラー適用・自動再起動の通し検証は、配布が可能になった段階で隔離Windows環境で行います。単体テスト・画面のsample・ローカル署名検証は、その実機受入とは区別します。
